# Domain docs

## Layout
Single-context: `CONTEXT.md` and `docs/adr/` at the repo root.

## Before exploring
Read `CONTEXT.md` and ADRs relevant to the work.
If these do not exist, proceed silently. Domain modeling creates
them lazily as terminology and decisions are resolved.

## Vocabulary
Use domain terms as defined in `CONTEXT.md`.
Reconsider invented synonyms; note genuine gaps for domain modeling.

## Decision conflicts
Explicitly flag proposals that contradict an existing ADR,
identifying the ADR and explaining why it should be reconsidered.
